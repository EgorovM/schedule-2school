# Расписание — МБОУ «Нюрбинская СОШ №2 им. М. С. Егорова»

Два не связанных между собой продукта в одной папке:

| Что | Где | Для кого |
|---|---|---|
| Сайт школы (одна страница) | `index.html`, публикуется из `docs/` | родители, ученики |
| Инструмент составления расписания | `raspisanie/` | заместитель директора по УВР |

Сайт: **https://egorovm.github.io/schedule-2school/**

## Публикация сайта

```bash
python3 tools/build_site_schedule.py   # расписание из data/schedule.json → index.html
python3 tools/build_pages.py           # index.html → docs/index.html (полная страница)
git add -A && git commit -m "обновил расписание" && git push
```

GitHub Pages пересобирает сайт сам, обычно за минуту. Источник настроен на
ветку `main`, папку `/docs`; `index.html` в корне — исходник без обвязки
`<html>`/`<head>`, её добавляет `build_pages.py`.

Первый шаг нужен только когда менялось расписание: он переносит на сайт то,
что завуч наредактировал в инструменте. Правки текста (контакты, кружки)
делаются прямо в `index.html`, дальше сразу второй шаг.

## Инструмент расписания

### Запуск

```bash
python3 -m raspisanie                       # откроет http://127.0.0.1:8770
python3 -m raspisanie --check               # только проверить и вывести список нарушений
python3 -m raspisanie --import "путь/расписание 26-27.xlsx"   # перечитать рабочий файл
```

Нужен Python 3.10+ и `openpyxl` (только для импорта и выгрузки в Excel):
`pip3 install openpyxl`. Больше никаких зависимостей нет: сервер на стандартной
библиотеке, интерфейс — обычная страница без сборки.

### Что он делает

**Расписание.** Сетка по классам: день × урок, у каждого урока балл трудности и
учитель. Урок перетаскивается мышью — в пустой слот переносится, в занятый
меняется местами со стоящим там уроком. Над сеткой — сумма баллов за каждый день
и её доля от недели рядом с нормой.

**Конструктор.** Собирает расписание с нуля по учебному плану. Задача из тех,
где точного быстрого решения не существует, поэтому работа идёт в два приёма:
жадная расстановка даёт первый допустимый вариант, дальше локальный поиск с
отжигом меняет уроки местами, пока сумма штрафов падает. Требования разведены по
весу — накладка учителя стоит 10000, отступление от диапазона МР считается по
процентным пунктам, пожелание педагога дороже, если отмечено обязательным.

Результат сначала показывается рядом с текущим расписанием, и только кнопка
«Применить» его заменяет; прежний вариант остаётся в `data/backups`.

На данных школы за 20 секунд расчёта получается расписание без единого нарушения
норматива и без накладок учителей — при том, что в исходной раскладке их больше
сотни.

**Нагрузка.** Учебный план: сколько часов какого предмета в классе и кто ведёт.
Часы выводятся из расписания, учителя проставляются кнопкой «Заполнить
автоматически»: классный руководитель 1—4 класса получает все предметы своего
класса, остальные позиции раздаются предметникам с балансировкой — параллель
достаётся разным педагогам, потому что у 5а, 5б и 5в один и тот же предмет часто
стоит в один и тот же час. Потолок автораспределения — 30 часов в неделю.

**Пожелания педагогов.** Четыре вида: не ставить в такой-то день, не больше N
уроков в день, нужен свободный день, ставить не позже N-го урока. Каждое может
быть обязательным (конструктор выполнит) или желательным (учтёт, если не мешает
нормативам).

**Учителя.** Недельная сетка одного педагога, его нагрузка и окна.

**Проверки.** Всё, что расходится с нормативом, с указанием пункта документа:

- предельная недельная нагрузка (СанПиН 1.2.3685-21, табл. 6.6);
- число уроков в день, включая правило «пять уроков один раз в неделю»;
- распределение трудности по дням недели (МР 2.4.0331-23, оба варианта);
- самый трудный предмет дня стоит первым или последним уроком;
- сдвоенные уроки в 1—4 классах;
- один предмет три раза за день;
- учитель в двух классах одновременно, кабинет занят дважды, окна;
- предметы, для которых балл трудности не задан.

Внеурочная деятельность (ВУД) в предельную аудиторную нагрузку не входит и
считается отдельно.

**Замены.** Отмечаете отсутствующего на дату — инструмент показывает его уроки и
для каждого подбирает, кто свободен в этот час: сначала учителя того же
предмета, затем остальные по возрастанию дневной нагрузки. Замены пишутся в
`data/substitutions.json`. Кнопка «Печать листа» даёт лист на день.

**Баллы.** Таблица трудности. По умолчанию — официальные значения СанПиН
(табл. 6.9 для 1—4, 6.10 для 5—9, 6.11 для 10—11). Своё значение в ячейке
перекрывает норматив и сохраняется в `data/scores.json`.

### Данные

```
data/schedule.json        рабочее расписание (правится через интерфейс)
data/substitutions.json   отсутствия и замены
data/scores.json          свои баллы трудности, перекрывают СанПиН
data/backups/             копия перед каждым изменением, хранится 40 последних
```

Импорт берёт лист **«РАСП С БАЛЛ»** (5—11 классы) и **«расписание нач классы»**
(1—4). Лист «РАСП БЕЗ БАЛЛОВ» не используется: в нём потерян класс 10в, сдвинуты
кабинеты и другие звонки.

### Что проверить перед тем, как доверять результату

**Расстановку учителей.** В файле 26/27 её нет — она есть только в 1—4 классах,
где номер педагога стоит перед названием предмета. Всё остальное автоназначение
выводит из прошлогоднего листа «прием» и из графы «предмет» в списке
педработников. Это догадка, и её надо просмотреть на вкладке «Нагрузка»: пока
там стоит не тот учитель, конструктор будет разводить не тех людей.

**Часы учебного плана.** Они посчитаны по текущему расписанию, а не взяты из
утверждённого плана. Если в расписании предмет стоял 3 раза, конструктор и
поставит 3 — даже если по плану положено 4.

### Чего он не делает

Не делит класс на подгруппы: если иностранный язык ведут два учителя на две
группы, в плане это одна позиция с одним учителем. В исходном файле такие уроки
записаны как «35|18 Иностранный язык», импорт их распознаёт, но раскладывает как
один урок.

## Нормативные источники

- СанПиН 1.2.3685-21, гл. VI — табл. 6.6 (режим), 6.9—6.11 (шкалы трудности)
- СП 2.4.3648-20 — требования к организации учебного дня
- МР 2.4.0331-23 (Роспотребнадзор, 10.11.2023) — распределение трудности по дням недели

Все значения собраны в `raspisanie/sanpin.py`, каждое подписано источником.
